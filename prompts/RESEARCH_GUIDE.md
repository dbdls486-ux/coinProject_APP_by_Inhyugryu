# 국내 리서치 수집 지침 (매일)

결과물은 `schema/research.schema.json`을 만족하는 **`data/research/index.json` 하나**다. 앱의 `뉴스 → 국내 리서치` 탭이 이 파일만 읽는다.
수집 대상과 방법 힌트는 `data/research/sources.json`에 있다. 이 파일은 사람이 관리한다 — 수집 작업은 **읽기만** 한다.

## 0. 목적 한 줄
기관 홈페이지 바로가기가 아니라 **개별 보고서가 모이는 피드**. 사용자는 카드 하나를 눌러 그 보고서 원문(글 또는 PDF)을 연다.

## 1. 포함 기준 — 국내 기관 + 한국어
- **국내 기관이 직접 발행**하고 **한국어 본문 또는 공식 한국어판**이 있는 가상자산·블록체인 보고서.
- 국내 기관이 미국 규제·해외 프로젝트를 분석한 글도 포함한다 (주제가 아니라 발행 주체와 언어가 기준).
- 영문 제목이라도 본문이 한국어면 포함한다 (포필러스 `/ko/` 글의 영문 제목 등).
- 한·영판이 둘 다 있으면 **한국어판 한 건만**. 영문판 URL은 넣지 않는다.
- 종합 연구기관(자본시장연구원·한국금융연구원·한국은행·증권사)은 **디지털자산과 직접 관련된 보고서만**:
  제목·요약에 디지털자산 / 가상자산 / 암호화 자산 / 암호화폐 / 비트코인 / 이더리움 / 스테이블코인 / 토큰화 / 토큰증권(STO) / 블록체인 / CBDC / 디파이 중 하나.
- **해외 리서치는 수집도 표시도 하지 않는다**: Glassnode, Coin Metrics, a16z, Messari, Galaxy, Delphi, Kaiko, Binance Research 등. `sources.json`의 `excluded_foreign` 참고.
- 쟁글이 다른 국내 기관의 보고서를 다시 올린 경우(같은 제목, 또는 본문에 '출처/제공: 디스프레드' 등) **원 발행기관 쪽 한 건만** 남긴다.
- 디지털엑스 리서치 = 옛 코빗 리서치센터(2026년 사명 변경). 같은 PDF가 두 경로로 보이면 한 건만.

## 2. 보고서 한 건의 필드 — 확인한 것만 적는다
| 필드 | 규칙 |
|---|---|
| `url` | 보고서 **원문** 주소. 글이면 글 주소, PDF 발간물이면 PDF 주소. 홈·목록 페이지·검색 결과 주소 금지. 실제로 열어 제목이 일치하는지 확인한 주소만 넣는다 |
| `title` | 기관이 쓴 제목 그대로 (앞의 `[Report]` 같은 말머리는 유지해도 된다) |
| `publishedAt` | 기관이 표시한 **실제 발행일** `YYYY-MM-DD` (기관이 월까지만 표시하면 `YYYY-MM`). RSS pubDate, 글의 날짜 표기, PDF 표지 날짜 순으로 찾는다. **못 찾으면 키를 생략**한다. 수집일을 발행일로 쓰지 않는다 |
| `summary` | 기관이 제공한 요약·부제·첫 문단을 **그대로 300자 이내**로 자른다. 내가 요약을 새로 쓰지 않는다. 없으면 키를 생략 |
| `collectedAt` | 처음 넣은 시각 ISO 8601. 이미 있는 항목은 바꾸지 않는다 |
| `pdf` | url 이 PDF 이면 true |
| `lang` | 항상 `"ko"` |
| `id` | `<source>:<url 의 고유 부분>` (slug, 숫자 id, uuid). 한 번 정하면 바꾸지 않는다 |

## 3. 수집 절차
1. 저장소를 받고 `data/research/sources.json`, 기존 `data/research/index.json`, 이 지침을 읽는다.
2. 기관마다 `collect.try` 의 주소를 **위에서부터** 시도한다. RSS/피드가 있으면 그것을 쓰고, 없으면 목록 페이지(또는 사이트맵)에서 개별 글 주소를 모은다.
   - WebFetch 로 목록을 읽을 때는 "모든 항목을 제목·주소·날짜·요약 순으로 빠짐없이 나열하라"고 지시하고, 주소는 **페이지에 실제로 있는 것만** 받아 적는다. 주소를 추측해 만들지 않는다.
   - 기관당 **이번 실행에서 새로 추가하는 보고서는 최대 15건**(첫 실행은 최신순 15건). 과거 자료는 다음 실행에서 이어서 쌓인다.
   - 새 보고서는 가능하면 원문 페이지를 한 번 더 열어 제목·발행일·언어(한글 비율)를 확인한다. 열리지 않거나 제목이 다르면 넣지 않는다.
3. 기관 상태를 기록한다:
   - 수집 성공 → `status: "ok"`, `lastOk: 오늘`, `method` 에 실제로 쓴 방법.
   - 이번 실행에서 실패했지만 기존 항목이 있음 → `status: "stale"` (기존 항목은 **그대로 둔다**. 지우지 않는다).
   - 접근 차단·로그인 필요·목록을 구조적으로 읽을 수 없음 → `status: "blocked"`, `note` 에 이유 한 줄. 기존 항목이 있으면 둔다.
   - 보고서 단위 수집을 아직 설계하지 못함 → `status: "link_only"`.
   한 기관이 실패해도 **다른 기관 수집과 파일 쓰기는 계속**한다. 전부 실패해도 기존 index.json 은 덮어쓰지 않는다.
4. 병합: 기존 `items` + 새 항목. `id` 가 같으면 기존 것을 유지하되 비어 있던 `publishedAt`/`summary` 는 채워도 된다. 같은 제목이 두 기관에 있으면 1절의 규칙으로 하나만.
   정렬은 앱이 하므로 순서는 중요하지 않지만, 보기 좋게 `publishedAt` 내림차순으로 둔다. `sources[].count` 를 다시 센다.
5. 검증 (python): `json.load`; 스키마의 `required` 전부 존재; 모든 `url` 이 `https://` 로 시작하고 기관 홈·목록 주소와 같지 않음; `publishedAt` 형식; 영문 전용(한글이 전혀 없는 제목 + 한국어판 아님) 항목이 0건; 해외 기관 id 가 0건; 같은 `url` 중복 0건.
6. `updatedAt` 을 KST 로 적고 커밋: `research: YYYY-MM-DD HH:MM` → push.

## 4. 하지 말 것
- 발행일·요약을 **지어내지 않는다**. 모르면 생략.
- 기관 홈페이지·목록·검색 결과 주소를 보고서 `url` 로 쓰지 않는다.
- 해외 기관·영문 전용 보고서를 넣지 않는다.
- 기존 항목을 삭제하지 않는다 (잘못 들어간 해외·영문 항목은 예외: 삭제하고 `note` 에 적는다).
- `data/research/` 밖의 파일을 수정하지 않는다.
