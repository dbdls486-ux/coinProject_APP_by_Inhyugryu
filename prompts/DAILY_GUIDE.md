# 데일리 시장 브리프 작성 지침 (매일 09:00 KST)

결과물은 `schema/daily.schema.json`을 만족하는 JSON 한 개를 `data/daily/YYYY-MM-DD.json`에 저장하고
`data/daily/index.json` 맨 앞에 `{ "id", "date", "regime", "title", "moverCount" }`를 추가한다.

## 0. 목적 한 줄
독자가 아침에 휴대폰으로 열어 **10초 안에 "시장이 어땠고, 어떤 움직임이 중요했고, 다음에 뭘 볼지"** 파악한다.
첫 화면(제목 + 3줄 요약 + 지표 카드 3개)만 읽어도 오늘의 시장 판단을 알 수 있어야 한다.

## 1. 분석 기간과 데이터
- 조회: 발행일 08:30 KST 전후. `asOf`에 기록.
- 기간: 직전 24시간. 월요일은 금요일 08:30부터 72시간. `window`에 사람이 읽는 형태로 적는다
  (예: "최근 72시간 (11/6 09:00 → 11/9 09:00 KST)").
- 출처: 가격·시총·거래량 CoinGecko / 파생 Coinglass / ETF Farside·SoSoValue / 온체인 DefiLlama.
- 선정: 시총 300위 이내 + 24h 거래량 ≥ 시총의 2% + 주요 거래소 상장. 미달은 `excluded`에 이유와 함께.

## 2. 첫 화면 (起)
1. **`title`**: 그날의 차이가 드러나는 한 문장, 48자 이내. 날짜·장세 표시는 넣지 않는다.
   예: "최근 72시간, 이더리움이 비트코인보다 더 크게 하락했다". 모든 날이 "하락" "상승"으로 끝나지 않게,
   그날 가장 특징적인 차이(ETH vs BTC, 알트 vs 메이저, 현물 vs 선물, 개별 종목)를 고른다.
2. **`tldr` 3줄**: ① 시장에서 일어난 일 ② 그 판단을 뒷받침하는 수치(기간 포함) ③ 다음에 확인할 변화.
   제목에 쓴 말은 반복하지 않는다.
3. **`keyMetrics` 최대 3개**: 오늘의 판단에 실제로 쓰인 지표만. 카드 하나 = 대표 숫자 **하나**.
   - `value`: "4.12억 달러 순유출"처럼 숫자+단위+방향. 집계 전이면 **"미집계"**.
   - `basis`: "11월 6일 거래일 기준 · Farside"처럼 기간과 출처를 작게.
   - `details`: 이전 거래일·종목별 내역은 여기(펼쳐보기). 첫 화면에 여러 날짜를 같은 크기로 늘어놓지 않는다.
4. `regime`: 상승장/하락장/횡보장/혼조 — 작게 표시될 뿐이므로 제목에 의존하지 말고 정확히.

## 3. 숫자 표기 규칙 (전 구간 공통)
- **모든 숫자 옆에 기간**: "72시간 -5.0%", "24시간 청산 11.6억 달러", "11/6 거래일 ETF -4.12억 달러".
- 아직 집계되지 않은 값은 **"미집계"** (빈칸·추정치 금지).
- 금액은 "4.12억 달러", "1,281.7백만 달러"처럼 단위를 붙여 한 덩어리로. 폰 너비에서 금액과 단위가 갈라지지 않도록
  숫자와 단위 사이에 띄어쓰기를 넣지 않는다 ("4.12억달러"가 아니라 "4.12억 달러"는 허용하되 단위를 줄바꿈 불가 처리는 앱이 한다).
- 용어는 그날 **처음 나올 때만** 괄호 풀이: OI(미결제약정: 아직 청산되지 않은 선물 계약 총액), 펀딩비, 숏 스퀴즈, 베이시스.

## 4. 본문 — 종목별 (承·轉)
각 `movers[]`는 반드시 이 순서다.
1. **`happened` — 무슨 일이 있었나**: 날짜·시각이 붙은 사실 1~3줄. 사건이 없으면 "확인된 개별 사건 없음".
2. **`reaction` — 시장이 어떻게 반응했나**: 가격·거래량·OI·청산 숫자와 기간 1~3줄.
3. **`watch` — 다음에 무엇을 보면 되나**: 1줄.

`causeType`은 아래 기준으로만 고른다 (가장 중요한 규칙):
| causeType | 조건 |
|---|---|
| **확인된 원인** | 사건 시각이 가격 반응보다 **앞서고**, 반응 수치(거래량·OI·넷플로우)까지 확인 |
| **가능한 배경** | 사건과 가격이 **같은 날 움직였다는 것만** 확인. 선후나 반응 수치는 미확인 |
| **수급 주도** | OI/시총·선물/현물 비·청산·펀딩이 움직임을 설명. 개별 사건은 없거나 미확인 |
| **시장 베타** | 시장 전체 움직임 범위 안 (BTC 대비 초과분이 작음) |
| **원인 불명** | 위 어느 것도 아님. 이것은 실패가 아니라 정직한 결과 |

- 사건이 가격 반응 **이후**에 나왔으면 원인이 아니다 → `caveat`에 "발표 N시간 전 이미 상승 시작" 기록.
- 사건과 가격 변동 사이가 5일 이상이면 **중간 반응(TVL·넷플로우·거래량)이 숫자로 있을 때만** 원인으로 쓴다.
- "~로 보인다", "~로 풀이된다"만 있고 숫자·시각이 없는 문장 금지. 섹터 내러티브를 개별 코인 원인으로 쓰지 않는다.
- `confidence`: A=사건·시각·반응 모두 확인 / B=사건 확인, 연결은 정황 또는 수급 지표만 / C=추정 수준.

## 5. 마무리 (結)
- `watchNext` 최대 4줄: 시각·이벤트·지표. 예: "11/10 22:30 KST 미국 10월 CPI", "BTC ETF 11/9 거래일 집계(11/10 07시경 Farside)".
- `highlight` 3~4문장: 오늘 가장 배울 점. 사건이 있는 움직임 vs 수급만 있는 움직임을 대비시키면 좋다.
- `market`: 시장 전체 표(펼쳐보기). BTC·ETH·전체 시총·도미넌스·청산·공포탐욕. 각 값에 기간.

## 6. 문체
- 짧은 문장(60자 이내), 숫자 우선, 감탄·전망·권유 없음. 굵게(**)는 핵심 숫자 한두 곳에만.
- 커밋 메시지: `daily: <date>`
